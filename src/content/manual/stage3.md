# 운영 매뉴얼 — Stage 3 · 서비스 오픈 (L4 · 소켓 · HTTP)

네트워크는 정상이야. 이제 web 서버에서 수강신청 앱(모놀리식 앱)을 켜고, 학생들이 실제로 접속하게 만드는 단계야.
처음엔 베타 테스터 몇 명만 접속하고, 학생 공지도 아직 안 올라왔어. 문제는 장애 경보와 함께 하나씩 나타나.

## 이번 단계 목표
1. web 서버에 접속해 수강신청 앱 실행하기
2. curl 로 /enroll 페이지를 직접 요청해서 200 OK 받기

## 핵심 개념
- 포트 · L4 (비유: 건물 안 호실 번호) — IP가 건물 주소라면 포트는 호실 번호. 한 컴퓨터 안에서 어떤 프로그램에게 갈지 정해. 웹(HTTP)은 보통 80번. 손님과 서버가 다른 호실 앞에 서 있으면 못 만나.
- TCP vs UDP (비유: 번호 매긴 등기우편 vs 엽서) — TCP는 먼저 연결하고(3-way handshake: SYN "얘기할래?" → SYN-ACK "응, 너도?" → ACK "응!") 순서·도착을 챙겨. UDP는 그냥 던져.
- 소켓 · 멀티스레드 서버 (비유: 프로그램의 전화기 · 전화마다 도우미 한 명씩) — 서버는 소켓으로 연결을 받아. 한 번에 한 명만 받는 동기(single) 서버는 손님이 몰리면 줄이 끝없이 길어져. 연결마다 스레드(도우미)를 붙이면 동시에 처리해.
- HTTP · 상태 코드 (비유: 주문서와 번호표) — 요청(GET /enroll)을 보내면 응답이 와. 200 OK = 여기 있어요, 404 Not Found = 그런 메뉴 없어요, Connection refused = 그 호실엔 아무도 안 받아요.

## 쓸 수 있는 명령어
| 명령 | 뜻 |
|---|---|
| ssh <이름 또는 IP> / exit | 다른 장비 접속 / 관리 PC로 돌아오기 |
| server status | (web 서버에서) 앱 상태, 포트, 스레드 방식, 가진 경로 목록 보기 |
| server start / server stop | 앱 실행 / 중지 |
| server set port <번호> | 앱이 기다리는 포트 바꾸기 |
| server set threads single\|multi | 직원 한 명 방식 / 요청마다 도우미 방식 |
| ports | 이 장비에서 열려 있는(LISTEN) 포트 목록 |
| curl [-v] http://<이름>[:포트]/<경로> | 로봇 손님처럼 HTTP 요청 보내기 (-v 는 handshake 과정까지 보여줌). web 서버 안에서는 localhost 로 자기 자신에게 요청할 수도 있어 |
| notice show / notice set <경로> | 학생 공지에 적힌 주소 보기 / 고치기 (공지가 올라온 뒤에만) |
| ip addr, ping, dhcp, dns list | Stage 2 네트워크 도구도 그대로 쓸 수 있어 |
| help, clear, hint, hostname | 공통 |

- server 명령은 웹 서버가 있는 장비(web)에 접속해야 써져. 관리 PC에서 치면 "먼저 web 에 접속하세요"가 나와.

## 결과 읽는 법
- `ports`: `LISTEN 0.0.0.0:<번호> enroll-app` 줄이 앱이 기다리는 호실이야. sshd(22)는 원격 접속용.
- `curl` 결과:
  - 초록 JSON 응답 → 200 OK (정상)
  - `Connection refused` → 그 포트에서 듣는 프로그램이 없음 (앱 꺼짐, 또는 포트가 다름)
  - `{"error":"Not Found"}` → 서버는 살아 있지만 그 경로(메뉴)가 없음 = 404
  - `Timed out` → 네트워크 길 문제 (Stage 2 점검으로)
- `server status` 의 스레드: `single (직원 한 명)` 은 노란색 경고, `multi` 는 초록.

## 장애 유형별 점검 순서
### A. "연결이 거부되었습니다" (포트 불일치)
1. 앱이 켜져 있는지: web 에서 `server status` → running?
2. 학생들은 몇 번 호실로 와? 웹 기본값(80)을 떠올려.
3. 서버는 몇 번에서 기다려? `ports` 또는 `server status` 의 포트.
4. 둘이 다르면 손님과 서버가 다른 문 앞에 서 있는 거야. curl 에 포트를 붙여 보면 확실히 비교돼.

### B. 느려지다 타임아웃 (한 명씩만 처리)
증상 예: "베타 테스터가 300명으로 늘었는데 페이지가 한참 걸리다 타임아웃"
1. 대시보드: 서버는 살아 있는데 응답시간이 엄청 길어 → 죽은 게 아니라 줄이 긴 것.
2. web 에서 `server status` → 스레드 방식 확인. single 이면 카운터 직원이 한 명.
3. 손님 수(접속자 rps)와 직원 수를 비교해서 생각해봐.

### C. 일부 학생만 404 (경로 오타)
증상 예: "공지 링크 누르면 Not Found, 직접 주소 친 학생은 괜찮대요"
1. 서버는 정상 → 문제는 "어떤 주소로 왔냐"야.
2. `notice show` 로 공지에 적힌 경로를 봐.
3. `server status` 의 경로 목록과 한 글자씩 비교. curl 로 두 경로를 각각 요청해서 200/404 를 비교하면 확실해.

## 힌트 줄 때 참고
- 포트 번호 같은 정확한 값과 완성 명령은 말하지 마. "어디를 비교하면 되는지"만.
- 상태 코드는 식당 비유(번호표, 없는 메뉴, 닫힌 창구)로 설명해줘.
