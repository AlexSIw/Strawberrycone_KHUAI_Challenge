# 운영 매뉴얼 — D-3 · 서비스 오픈 (포트 · HTTP · L4 · MSA)

수강신청까지 3일. 수강신청 웹 서비스를 여는 날이야. 먼저 써보기로 한 학생들(베타 테스터)만 들어와: 1초에 20건 정도(20 rps: 1초에 들어오는 요청 수).
수강신청 앱은 WEB-01(이름 web)에 설치돼 있지만 꺼져 있고, 엉뚱한 포트로 설정돼 있어. 학생들은 대표 이름 sugang 하나로 들어오고, L4(입구 안내원)가 뒤의 서버로 나눠 보내.
그리고 어제 리허설 때 알림 메일 기능 버그 하나로 앱 전체가 멈췄어. 오늘 앱을 기능별 서비스로 나눠.
네트워크(VLAN·게이트웨이·DNS)는 어제 다 만들어 뒀어. 터미널은 관제실 관리 PC(책상)에서 열어.

## 이번 날 목표
1. web 서버에 원격 접속해 수강신청 앱 실행 (ssh web → server start)
2. 학생들이 찾아오는 문(80번 포트)에서 앱이 기다리게 하기 (curl로 확인)
3. L4-01에 web 서버 등록하고, 헬스체크 경로를 /health 로 맞추기
4. 관리 PC에서 학생처럼 http://sugang/enroll 요청해 200 OK 받기
5. 관제 화면 SMS 탭에서 서비스 응답 상태 보기
6. 관제실 설계 보드에서 수강신청 앱을 기능별 서비스로 나누기 (svc list로 확인)

## 길 그림
학생 → 인터넷 → 경계 라우터 → 방화벽 → 코어 → L4-01 (대표 주소 VIP: sugang = 10.10.30.100) → 풀에 등록된 서버(web:80) → 수강신청 앱
- L4 는 쌍(L4-01 · L4-02)이고, 켜져 있는 첫 번째가 일해. 설정은 L4-01 에 접속해서 해.

## 핵심 개념
- 포트 (비유: 건물 안 호실 번호) — IP가 건물 주소라면 포트는 호실 번호. 웹(HTTP)은 보통 80번. 손님과 서버가 다른 호실 앞에 서 있으면 못 만나(연결 거부).
- 소켓 · 스레드 (비유: 프로그램의 전화기 · 전화마다 도우미) — 앱을 켜면 정해진 포트에서 손님을 기다려(LISTEN). 직원 한 명(single) 방식은 손님이 몰리면 줄이 길어져. 오늘 접속량(초당 20건)에서는 괜찮아.
- TCP · HTTP (비유: 번호 매긴 등기우편 · 주문서와 번호표) — TCP는 SYN → SYN-ACK → ACK 세 번 인사(3-way handshake)부터 해. 그다음 HTTP 주문서(GET /enroll = "신청 페이지 주세요")가 가고 상태 코드가 돌아와: 200 OK = 여기 있어요, 404 Not Found = 그런 메뉴 없어요, Connection refused = 그 호실엔 아무도 안 받아요.
- L4 로드밸런서 · 헬스체크 (비유: 식당 입구 안내원과 "자리 있어요?" 순찰) — 학생들은 대표 주소(VIP) 하나로 오고, L4가 서버 목록(풀)에 나눠 보내. L4는 서버마다 정해진 경로·포트로 "살아 있니?"를 계속 물어보고(헬스체크), 대답이 없는 서버는 DOWN으로 보고 손님을 안 보내. 헬스체크 경로가 서버에 없거나 포트가 틀리면 멀쩡한 서버도 DOWN이 돼.
- NMS · SMS · 폴링 (비유: 정해진 간격으로 도는 순찰) — 관제 시스템은 장비·서비스에 주기적으로(약 15초마다) 상태를 물어봐(SNMP 폴링). 숫자로 보는 문제(사용률, 오류, 응답시간)는 다음 순찰 때에야 경보가 돼. 장비가 스스로 알리는 trap·syslog 는 바로 떠.
- 경보 등급 — critical = 서비스가 멈추거나 깨짐, major = 서비스는 되지만 예비가 없음(이중화 상실), minor = 일부 기능·한계 근처, warning = 지켜볼 것.
- MTTD · MTTR — MTTD = 장애 시작 → 경보 확인(ACK)까지, MTTR = 장애 시작 → 복구까지. 학생 민원보다 경보를 먼저 보고 확인하는 게 관제의 일.
- 모놀리스 → MSA (비유: 주방 하나인 큰 식당 → 푸드코트) — 기능이 전부 한 덩어리(모놀리스)면 알림 버그 하나에도 전체가 멈춰. 하는 일(업무) 단위로 작은 서비스로 나누면(MSA) 탈 난 매장만 문을 닫아(장애 격리). 화면·로직·DB 같은 기술 층으로 자르면 안 돼.
- 담당팀 이관 (비유: 우리 가게 일이 아니면 건물 관리실에 연락) — KHU 포털·LMS·웹메일·도서관은 다른 팀이 운영해. 우리 네트워크는 멀쩡한데 그 서비스만 아프면, 증상을 정리해서 그 팀에 넘기고 해결될 때까지 지켜봐.

## 쓸 수 있는 명령어
### 관리 PC·서버 (리눅스)
| 명령 | 뜻 |
|---|---|
| ssh <이름 또는 IP> / exit | 다른 장비 접속 / 관리 PC로 돌아오기 |
| server status | (web 에서) 앱 상태, 포트, 스레드 방식, 가진 경로 목록 |
| server start / server stop | 앱 실행 / 중지 |
| server set port <번호> | 앱이 기다리는 포트 바꾸기 |
| server set threads single\|multi | 직원 한 명 방식 / 요청마다 도우미 방식 |
| ports | 이 장비에서 열려 있는(LISTEN) 포트 |
| curl [-v] http://<이름>[:포트]/<경로> | 로봇 손님처럼 HTTP 요청 보내기 (-v 는 인사 과정까지 보여줌). http://web/… = 서버에 직접, http://sugang/… = 학생처럼 L4를 거쳐서 |
| svc list | 서비스별 상태(up/DOWN), 서버 수, 처리 용량 |
| svc restart <서비스> | 그 서비스만 재시작 |
| svc deps <서비스> | 그 서비스가 부르는 서비스·DB |
| ping, traceroute, nslookup, ip addr, hostname | 네트워크 도구 (D-4와 같음) |
| help, clear, hint | 공통 |
- server 명령은 web 에 접속해서 써야 해. 관리 PC에서 치면 "먼저 web 에 접속하세요"가 나와.

### L4 (ssh L4-01 한 뒤)
| 명령 | 뜻 |
|---|---|
| lb status | 대표 주소(VIP), 일하는 L4, 세션 수 |
| lb pool | 풀에 등록된 서버와 각 서버의 헬스체크 결과(UP/DOWN) |
| lb pool add <서버> <포트> / lb pool del <서버> | 풀에 서버 등록 / 빼기 |
| lb pool enable\|disable <서버> | 서버를 잠깐 빼거나 다시 넣기 |
| lb health | 헬스체크 설정 (방식, 포트, 경로) |
| lb health set path <경로> / lb health set port <번호> | 헬스체크 경로 / 포트 바꾸기 |

### 스위치 (IOS) · DNS · DHCP
- D-4 매뉴얼과 같아. show interfaces status, show logging 등은 업링크 장애 볼 때 써.

### 관제 화면 · 설계 보드
- NMS: 장비 지도와 링크 색, 장비를 누르면 포트 상태·로그. 경보 목록에서 확인(ACK), 쿠사수에게 묻기, 얕은 장애(교내 서비스)에는 "담당팀 이관" 버튼.
- SMS: 수강신청·서비스별 상태와 응답시간, KHU 포털·LMS·웹메일·도서관 응답시간과 운영 팀.
- 설계 보드(E): 모놀리스의 기능 카드를 서비스로 묶는 퍼즐. 하는 일 단위로 묶어야 통과(로그인 · 과목조회 · 장바구니 · 신청 · 알림).

## 결과 읽는 법
- curl:
  - 초록 데이터(JSON: { } 로 감싼 데이터) = 200 OK, 정상
  - Connection refused = 그 포트에서 기다리는 프로그램이 없음 (앱 꺼짐, 또는 포트가 다름)
  - {"error":"Not Found"} = 서버는 살아 있지만 그 경로가 없음 = 404
  - Timed out = 길 문제, 또는 L4 뒤에 살아 있는 서버가 하나도 없음
- ports: LISTEN 0.0.0.0:<번호> enroll-app 줄이 앱이 기다리는 호실.
- lb pool: 서버마다 UP/DOWN. 서버가 켜져 있는데 DOWN이면 헬스체크가 묻는 경로·포트를 의심.
- lb health: http · 포트 · 경로. 이 경로·포트가 server status 의 포트·경로 목록에 있어야 해.
- svc list: STATE up(초록)/DOWN(빨강), CAPACITY(처리 용량) = 서버 수 × 한 대 용량.
- 관제 화면 수강신청 가용성 = 요청 중 제대로 처리된 비율.

## 장애 유형별 점검 순서
### A. 수강신청 사이트 접속 불가, 웹 서버는 멀쩡 (L4 헬스체크 오류)
증상 예: "수강신청 사이트가 갑자기 안 열려요! 웹 서버는 멀쩡히 켜져 있다는데요?" · 경보 "L4-01 서버 풀 멤버 전부 DOWN"
1. 서버에 직접(curl http://web/enroll) vs 학생처럼(curl http://sugang/enroll) 비교. 직접은 되고 대표 주소만 안 되면 L4 쪽 문제.
2. ssh L4-01 → lb pool: 서버가 DOWN 으로 보이는지.
3. lb health: 헬스체크가 묻는 경로·포트를 확인하고, web 에서 server status(포트·경로 목록)와 비교. 서버에 없는 경로거나 서버가 안 쓰는 포트면 L4는 멀쩡한 서버를 죽었다고 봐.
4. 해결 방향: 헬스체크 설정을 서버가 실제로 가진 경로·포트에 맞추기. 다시 lb pool 에서 UP 확인, curl http://sugang 으로 200 확인.
- 교훈: 헬스체크가 틀리면 L4는 멀쩡한 서버로도 손님을 안 보내. 그리고 민원과 경보 중 뭘 먼저 봤는지 = MTTD.

### B. 경보는 떴는데 서비스는 정상 (랙 스위치 업링크 하나 끊김)
증상 예: "관제 화면에 경보가 하나 떴는데, 학생들은 아무 문제 없대요. 이거 지금 봐야 해요?" · 경보 "TOR-01 인터페이스 링크 다운" (major)
1. 관제 화면 NMS에서 TOR-01을 열어 빨간(down) 포트를 찾고, 그 포트가 어디(코어 스위치)로 이어지는지 봐. TOR-01 에서 show interfaces status, show logging 으로도 볼 수 있어.
2. 서비스가 멀쩡한 이유: TOR-01 에서 코어로 가는 길이 여러 개고, 평소엔 STP(고리 방지 장치)가 하나를 막아 두다가 하나가 끊기면 막아 둔 길을 열어줘.
3. 그래도 지금은 예비가 없는 상태(major). 다음 고장엔 버틸 게 없어.
4. 전원·설정이 멀쩡한데 링크만 down 이면 L1(케이블)을 의심. 네트워크실 스위치에서 그 케이블을 테스트하고 새것으로 바꿔.
- 교훈: "서비스 영향 없음"이어도 이중화가 깨졌으면 major. 미루지 말고 고쳐.

### C. 알림 메일이 안 오는데 신청은 됨 (알림 서비스 다운)
증상 예: "수강신청 알림 메일이 안 온대요! …그런데 신청은 잘 되고 있대요?"
1. 관제 화면 수강신청 가용성: 알림이 죽어도 신청 성공률이 유지되는지 → 서비스를 나눈 덕분(장애 격리).
2. svc list 로 DOWN 인 서비스 확인.
3. 알림팀이 버그를 고친 새 버전(핫픽스)을 올려 뒀어. 그 서비스만 다시 시작하면 반영돼.

### D. 교내 서비스 하나만 느림 (다른 팀 시스템 → 담당팀 이관)
증상 예: "KHU LMS 접속이 너무 느리대요" · 경보 "KHU LMS 응답시간 4초 이상" (minor)
1. 관제 화면 SMS: 느린 게 그 서비스 하나뿐인지, 수강신청과 다른 교내 서비스도 느린지 비교.
2. 우리 네트워크 길이 문제라면 다른 서비스도 같이 느려야 해. 하나만 느리면 그 서비스 서버 쪽 문제.
3. SMS 에서 그 서비스를 운영하는 팀을 확인. 우리 담당이 아니면 직접 손대지 않아.
4. 해결 방향: 경보 목록의 "담당팀 이관" 버튼으로 그 팀에 넘기고, 응답시간이 돌아올 때까지 지켜봐. (이관해도 해결까지 시간이 걸리고, 그 시간도 복구 시간에 들어가)

### E. 목표가 안 넘어감
- 앱 실행: web 에 ssh 로 들어가서 server start. server status 로 running 확인.
- 80번 포트: server status 또는 ports 로 포트 확인. curl http://web/ 으로 200 이 오면 OK.
- L4: L4-01 에서 lb pool 에 web 서버(포트 80)가 등록돼 UP 이어야 하고, lb health 경로가 /health 여야 해.
- curl: 관리 PC에서 sugang 이름으로 요청해서 200 OK 를 받아야 해 (web 이름으로 직접 한 건 인정 안 됨).
- SMS: 관제 화면에서 SMS 탭을 열면 돼.
- 서비스 나누기: 설계 보드 퍼즐을 하는 일 단위로 풀면 완료. svc list 로 구조가 MSA 인지 확인.

## 힌트 줄 때 참고
- 장애 힌트에서는 경로, 포트 번호, 서버 이름을 붙인 완성 명령은 말하지 마. "무엇과 무엇을 비교할지"를 알려줘.
- 상태 코드는 식당 비유(번호표, 없는 메뉴, 닫힌 창구), L4는 입구 안내원 비유를 이어가면 쉬워.
- 교내 서비스 장애는 "우리 일인가?"부터 따지게 해줘. 이관 버튼 이름을 바로 말하지 말고 경보 목록에 있는 버튼을 살펴보게 해.
- 플레이어는 서버를 처음 접하는 일반인이야. L4, VIP, 헬스체크, MSA, rps 같은 말은 처음 쓸 때 쉬운 말로 한 번 풀어줘.
