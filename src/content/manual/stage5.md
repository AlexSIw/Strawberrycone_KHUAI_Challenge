# 운영 매뉴얼 — Stage 5 · "내 컴퓨터에선 되는데…" (Container · Docker)

2차 수강신청 대비로 신청 서버를 늘리는 중이야. 그런데 서버마다 설치 상태가 조금씩 달라서 새 서버에서 앱이 안 떠.
앱과 실행 환경을 통째로 포장하는 컨테이너로 해결하는 단계야.

## 이번 단계 목표
1. 새 서버(srv-new)의 배포 기록 확인하기
2. 관제실 설계 보드에서 Dockerfile(레시피 카드) 완성
3. 관리 PC에서 이미지 빌드 → 레지스트리에 push
4. srv-new 에서 컨테이너 실행

## 장비
- ops: 관리 PC (이미지 빌드·push 는 여기서). srv-old: 기존 신청 서버. srv-new: 새 서버. srv-db: DB 컨테이너가 도는 서버.
- 서버 랙 앞(E)에서도 각 서버 콘솔을 열 수 있어.

## 핵심 개념
- 설정 차이(configuration drift) — 서버마다 설치된 프로그램 버전이 조금씩 달라서 "내 컴퓨터에선 되는데" 문제가 생겨.
- VM vs 컨테이너 — VM은 컴퓨터 통째(운영체제 포함)를 흉내 내서 무겁고, 컨테이너는 앱과 필요한 것만 묶어서 가볍고 빨라.
- 컨테이너 · 이미지 (비유: 밀키트 원본(이미지)과 그걸로 만든 한 끼(컨테이너)) — 이미지로 묶으면 어느 서버에서나 똑같이 실행돼.
- Dockerfile (비유: 레시피 카드) — 어떤 재료(FROM 베이스 이미지)에 무엇을 넣고(COPY, RUN) 어떻게 실행할지(CMD) 적은 카드.
- 레지스트리 (비유: 마트 냉동고) — 만든 이미지를 올려두는 곳. 다른 서버는 여기서 꺼내(pull) 써.
- 포트 매핑 -p (비유: 길가 문 80번 → 주방 창구 8000번) — 컨테이너는 잠긴 방이야. 바깥(호스트) 포트와 안쪽(컨테이너) 포트를 이어야 손님이 들어와. Dockerfile 의 EXPOSE 는 "안쪽 창구 번호" 메모일 뿐이야.
- 볼륨 (비유: 식당 전용 사물함) — 컨테이너 안에 저장한 데이터는 컨테이너와 함께 사라져. 볼륨에 저장해야 남아.

## 쓸 수 있는 명령어
| 명령 | 뜻 |
|---|---|
| deploy log | (그 서버에서) 손으로 한 배포 기록 보기 |
| python --version | 그 서버에 설치된 Python 버전 |
| docker build -t <이미지:태그> . | Dockerfile 로 이미지(밀키트 원본) 만들기 (관리 PC) |
| docker push <이미지:태그> | 이미지를 레지스트리(냉동고)에 올리기 |
| docker pull <이미지:태그> | 레지스트리에서 이미지 받아오기 |
| docker images | 이 장비에 있는 이미지 목록 |
| docker run [-p 호스트:컨테이너] [-v 볼륨:/경로] [--name 이름] <이미지> | 이미지로 컨테이너(한 끼) 실행 (서버에 접속해서) |
| docker ps [-a] | 실행 중인(-a 는 멈춘 것까지) 컨테이너: IMAGE, STATUS, PORTS, VOLUME, NAME |
| docker rm -f <이름> | 컨테이너 지우기 |
| docker restart <이름> | 컨테이너 재시작 |
| docker logs <이름> | 컨테이너 로그 보기 |
| docker volume create <이름> / docker volume ls | 볼륨(사물함) 만들기 / 목록 |
| ssh, exit, ping, hostname, help, clear, hint | 공통 |

## 결과 읽는 법
- `deploy log` 실패 예: Python 버전이 맞지 않는다는 ERROR, 모듈을 못 찾는다는 에러 → 서버 환경이 기존 서버와 달라.
- `docker build` 가 "Dockerfile(레시피 카드)이 아직 없어요" → 설계 보드에서 레시피부터.
- `docker push` 가 "image does not exist locally" → 빌드부터. `docker run` 이 "레지스트리에도 없어요" → push 부터.
- `docker ps` 의 PORTS: `0.0.0.0:<바깥>-><안쪽>` 이면 연결됨. `(없음)` 이면 밖에서 못 들어와.
- `docker ps` 의 VOLUME: `-` 이면 데이터가 컨테이너 안에만 있음(지우면 사라짐).
- `docker logs db`: "Table enrollments is empty" 경고 = 빈 DB. data dir 줄에 "(컨테이너 안 · 지우면 함께 사라짐)"이면 볼륨이 없는 것.

## 장애 유형별 점검 순서
### A. 새 서버에서 앱이 안 뜸 (환경 차이)
1. srv-new 에 접속해서 `deploy log` → 어떤 에러인지 읽어.
2. `python --version` 을 srv-old 와 srv-new 에서 비교해봐. 다르지?
3. 서버마다 맞춰 깔기보다 앱+환경을 통째로 포장(이미지)하는 쪽으로.
4. 순서: 레시피(설계 보드) → 빌드 → 냉동고에 올리기 → 새 서버에서 꺼내 실행.

### B. 컨테이너는 Up 인데 접속 불가 (포트 매핑)
1. 그 서버에서 `docker ps` → STATUS 는 Up 인데 PORTS 칸이 비었는지 봐.
2. 앱은 컨테이너 안 8000번 창구에서 기다려. 학생은 길가 80번 문으로 와.
3. 실행 옵션에 바깥 문과 안쪽 창구를 잇는 설정이 있었어. 이미 뜬 컨테이너는 지우고 다시 실행해야 해.

### C. 재시작했더니 데이터 0건 (볼륨)
1. 대시보드: "신청 내역 0건! 데이터 유실".
2. srv-db 에서 `docker logs db` → data dir 이 컨테이너 안이었는지 확인.
3. `docker ps` 의 VOLUME 칸이 `-` 이면 사물함 없이 쓰고 있던 것.
4. 사물함(볼륨)을 붙여서 DB 컨테이너를 새로 실행하면 어젯밤 백업이 그 볼륨으로 복원돼.

## 힌트 줄 때 참고
- 포트 숫자 쌍이나 볼륨 옵션 같은 완성 옵션은 말하지 마. "PORTS/VOLUME 칸을 봐", "실행 옵션 중에 잇는 게 있어" 정도로.
- 밀키트 → 냉동고 → 한 끼, 사물함 비유를 이어가.
