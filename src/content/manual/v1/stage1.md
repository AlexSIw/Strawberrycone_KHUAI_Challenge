# 운영 매뉴얼 — Stage 1 · 랙과 전원, 케이블 (L1 물리 계층)

새 서버 3대(웹 서버 web = 사이트 화면 담당, DB 서버 db = 신청 기록을 보관하는 데이터 창고, 예비 서버 spare)를 설치하는 단계야.
순서는 랙 장착 → 전원 연결 → 케이블 연결. 물리적인 게 먼저야.

## 이번 단계 목표
1. 서버실 랙(서버를 꽂는 선반)에 서버 3대 장착 (랙 앞에서 E)
2. 전원실 PDU(서버용 멀티탭)에서 서버 전원 연결
3. 네트워크실 스위치(서버들을 잇는 연결 상자)에 서버 케이블 연결
- 케이블 목표는 전원 목표 다음에 열려. 케이블을 먼저 꽂아 둬도 괜찮아. 전원이 들어가는 순간 둘 다 완료로 쳐져.

## 핵심 개념
### OSI 7계층 · L1 물리 (비유: 7층짜리 우체국의 1층 = 실제 도로)
- 통신을 7층으로 나눠 보는 지도. L1은 데이터(0과 1, 비트)가 실제로 지나가는 케이블과 전기 신호야.
- 도로가 끊기면 위층(주소, 프로그램)이 아무리 멀쩡해도 편지가 못 가.
- 그래서 문제 찾기는 항상 L1(물리)부터!

### link LED
- 포트(케이블 꽂는 구멍) 옆 초록불 = 케이블 양쪽이 연결되어 신호가 오가는 상태(link UP: 연결 살아 있음).
- 꺼짐 = 케이블이 없거나, 끊겼거나, 반대쪽 장비가 꺼진 상태.
- 전원 LED와 link LED는 달라. 전기는 들어와도 link는 꺼질 수 있어.

### 전원: PDU · UPS (비유: 멀티탭과 비상 배터리)
- 전기가 오는 길: 바깥 전기(mains) → (UPS) → PDU A, 그리고 바깥 전기 → PDU B.
- PDU: 서버들에 전기를 나눠주는 멀티탭. A줄과 B줄 두 개가 따로 있어. 장비마다 A, B 플러그를 꽂을 수 있어.
- UPS: 정전되면 배터리로 잠깐 버텨주는 장치. PDU A 앞에 연결돼. 그래서 정전 때는 A줄만 전기가 남고, B줄은 꺼져.
- B줄은 정전 대비가 아니라 "A쪽이 고장 날 때" 대비야. PDU A 차단기가 내려가도 B줄은 살아 있어.

### 단일 장애점(SPOF) · 이중화 (비유: 다리가 하나뿐인 섬)
- 하나만 고장 나도 전체가 멈추는 지점. 이중화는 같은 걸 두 개 둬서 하나가 망가져도 버티게 하는 거야. 이 단계엔 두 가지가 있어.
- 바깥 전기 하나에만 기대는 것 → 정전이면 끝. 대비: UPS(비상 배터리).
- 전원을 한 줄로만 받는 것 → 그 줄(PDU·회로)이 고장 나면 끝. 대비: A·B 두 줄로 받기(이중 전원).

## 쓸 수 있는 도구
- 이 단계는 터미널 대신 손으로 해: 랙(서버실), PDU·UPS(전원실), 스위치·패치 패널(네트워크실)에서 E.
- 관리 PC는 아직 못 써. 서버에 IP 주소가 없어서 원격 접속이 안 되거든.
- 대시보드(Tab): 전원 패널(어느 장비에 전기가 오는지), 링크 패널(포트별 link 상태)을 볼 수 있어.
- 이 단계엔 터미널을 여는 곳이 없어 (Stage 2부터). 명령어 대신 장비 앞에서 E, 막히면 H(쿠사수 무전기).

## 장애 유형별 점검 순서
### A. 서버 하나만 불이 안 들어옴 / 링크 다운
증상 예: "DB 서버만 불이 안 들어와요. 다른 서버는 초록불인데…"
1. 대시보드 링크 패널: 어느 서버의 link가 DOWN인지 확인.
   - 정상: 모든 서버 link UP(초록).
   - 비정상: 한 서버만 DOWN.
2. 그 서버의 전원은 들어와? (전원 패널) 전원 OK인데 link만 DOWN이면 전기 문제가 아니라 "길" 문제야.
3. 네트워크실 스위치/패치 패널에서 그 서버 케이블의 양쪽 끝을 확인.
4. 케이블은 꽂혀 있는데 신호가 안 간다면 케이블 내부가 끊겼을 수 있어. 다른 케이블로 바꿔 보면 범인이 케이블인지 포트인지 좁혀져.
- 교훈: 전기는 들어와도 데이터는 못 지나갈 수 있어. L1부터 의심!

### B. 정전 · 건물 전체 전기 끊김
증상 예: "앗, 정전! 건물 전체에 전기가 나갔어요!! 서버들 괜찮아요?"
1. 대시보드 전원 패널: mains(외부 전기) OFF인지 확인.
2. 전원실 그림에서 전기가 흐르는 길을 따라가 봐. 정전 때 전기가 남을 수 있는 건 UPS 뒤의 PDU A뿐이야.
3. UPS가 PDU A에 연결돼 있는지 확인.
   - 비정상: UPS 미연결 → 정전 때 버틸 배터리가 없음 → PDU A도 꺼짐.
4. 장비마다 A줄을 받고 있는지 확인. B줄만 받는 장비는 UPS가 있어도 정전 때 꺼져.
   - 정상: UPS 연결 + 모든 장비(서버 3대, 스위치, 라우터)가 A줄을 받음. 그러면 모든 장비가 켜지고 경보가 풀려.
- 교훈: 바깥 전기 하나에만 기대면 그게 단일 장애점. UPS(비상 배터리)가 정전 동안 버텨줘. 단, 배터리 뒤 줄(A)을 받는 장비만.

### C. 정전도 아닌데 일부 장비만 꺼짐 (PDU 한쪽 고장)
증상 예: "전원실에서 '딱!' 하고 뭔가 내려가는 소리가 났어요! 정전은 아니라는데… 장비들 괜찮아요?"
1. 대시보드 전원 패널: mains 는 ON인데 꺼진 장비가 있어 → 정전이 아니라 전원 줄 문제.
2. 전원실 PDU A/B 불빛: 한쪽 PDU가 "차단기 내려감"이면 그 줄은 지금 전기가 없어. (차단기는 전기 기사가 점검한 뒤 올려줘. 플레이어가 직접 올릴 수는 없어)
3. 꺼진 장비와 멀쩡한 스위치·라우터를 비교: 표의 "받는 줄" 칸. 한 줄만 받는 장비가 그 줄과 함께 꺼진 거야.
4. 해결 방향: 살아 있는 줄로도 전기를 받게 해서, 줄 하나가 끊겨도 버티게 만들기(이중 전원).
- 교훈: 전원이 한 줄뿐이면 그 줄이 단일 장애점(SPOF). A·B 두 줄로 받으면 PDU 하나가 고장 나도 버텨.

### D. 목표가 안 넘어감
- 랙 장착: 서버 3대 모두 꽂았는지 (web, db, spare).
- 전원: 서버마다 최소 한 줄은 연결해야 해.
- 케이블: 서버마다 eth0 포트(서버의 첫 번째 네트워크 구멍)를 스위치 포트에 연결. 전원 목표가 끝나야 케이블 목표가 완료로 쳐져.

## 힌트 줄 때 참고
- 1단계 힌트는 "어디가 초록이고 어디가 꺼졌어?" 같은 관찰 질문.
- "케이블 교체", "UPS 연결", "A·B 둘 다 꽂기" 같은 정답 행동은 직접 말하지 말고, 볼 곳(양쪽 끝, 전원실의 배터리 장치, PDU 불빛, 표의 "받는 줄" 칸)을 가리켜줘.
- 정전(B)과 PDU 고장(C)은 다른 문제야. 정전은 UPS, PDU 고장은 이중 전원이 답이니 섞어서 말하지 마.
