# 운영 매뉴얼 — Stage 2 · 서로 대화하게 만들기 (L2/L3)

케이블은 다 꽂혔지만 서버들에 주소가 없어. 주소를 나눠주고, 서로 찾고, 밖으로 나가게 만드는 단계야.
터미널은 관제실 관리 PC(책상)에서 열어. 서버 랙 앞(E)이나 라우터 앞에서는 그 장비 콘솔이 바로 열려.

## 이번 단계 목표
1. 관리 PC에서 터미널 열기
2. DHCP 서버를 켜서 서버들에 주소 나눠주기
3. ping 으로 web 서버 응답 확인하기

## 장비
- ops: 관리 PC (지금 서 있는 곳). web: 웹 서버. db: DB 서버. spare: 예비 서버. r1: 라우터(게이트웨이).
- ops·라우터는 원래 고정(static) 주소야. 라우터 주소는 바꿀 수 없고, ops 를 DHCP 모드로 바꿔도 안내데스크가 ops 몫으로 예약된 같은 주소를 줘.
- 네트워크 정보(대역, 라우터 주소, DHCP 범위)는 관제실 설계 보드에 적혀 있어.

## 핵심 개념
- MAC 주소 (비유: 문패) — 장비마다 붙은 고유 이름표. 스위치는 문패를 보고 같은 네트워크 안에서 배달해.
- IP 주소 (비유: 도로명 주소) — 네트워크에서 장비를 찾는 주소. 한 주소는 한 장비만! 같은 주소가 두 집이면 택배가 엉망이 돼. 손으로 정할 땐 이미 누가 쓰는 주소가 아닌지 꼭 확인해. (라우터·관리 PC처럼 원래 고정 주소를 쓰는 장비도 있어)
- 서브넷 (비유: 동네) — 설계 보드의 네트워크 범위(/24) 안의 주소만 이 동네 주소야. 범위 밖 주소를 박으면 라우터가 길을 몰라서 아무도 못 찾아와.
- DHCP (비유: 주소 나눠주는 안내데스크) — 장비가 켜지면 IP·게이트웨이를 자동으로 나눠줘. 안내데스크가 문을 안 열면 새로 주소를 받으려는 장비는 못 받아. (이미 받은 주소는 문을 닫아도 그대로 써)
- DNS (비유: 전화번호부) — db 같은 이름을 숫자 IP로 바꿔주는 장부. 장부에 이름이 없으면 길이 멀쩡해도 못 찾아가.
- 게이트웨이 · 라우터 (비유: 건물 밖으로 나가는 문 · 우편 분류소) — 다른 네트워크(인터넷)로 나갈 때 거치는 라우터 주소. 문 위치를 잘못 알면 건물 안은 되는데 밖으로는 못 나가.
- ping — 상대에게 "들려?" 신호를 보내 대답이 오는지 보는 도구.

## 쓸 수 있는 명령어
| 명령 | 뜻 |
|---|---|
| help | 쓸 수 있는 명령어 보기 |
| ip addr | 지금 장비의 IP 주소 · 게이트웨이 · link 상태 · 모드(dhcp/static) 보기 |
| ip set dhcp / ip set static <ip> / ip set gw <ip> | 주소를 DHCP로 받기 / 고정 IP 설정 / 게이트웨이 설정 (라우터 자신의 주소는 바꿀 수 없어) |
| ping <이름 또는 IP> | 상대가 응답하는지 확인 (3번 보내고 몇 번 돌아오는지) |
| dhcp status / dhcp on / dhcp off | DHCP 서버 상태 · 나눠준 주소 목록 보기, 켜기, 끄기 |
| dns list | DNS 장부(이름 → IP) 보기 |
| dns add <이름> <IP> / dns del <이름> | DNS 장부에 이름 등록 / 지우기 |
| ssh <이름 또는 IP> | 다른 장비에 원격 접속 (exit 로 관리 PC로 돌아옴). ping 처럼 네트워크로 가: 이름 → DNS → 주소 → 그 주소의 장비 |
| hostname | 지금 어느 장비에 있는지 |
| clear, hint | 화면 지우기, 쿠사수 부르기 |

## ping 결과 읽는 법
- 정상: `3 packets transmitted, 3 received, 0% packet loss`
- `cannot resolve <이름>: Unknown host` → 이름을 IP로 못 바꿈. 전화번호부(DNS) 문제.
- `No route to host` (이 장비에 IP 주소가 없어요) → 내 장비에 주소가 없음. 안내데스크(DHCP) 문제.
- `Request timeout` + `100% packet loss` → 길이 막힘. 케이블/link, 또는 게이트웨이 문제.
- 3개 중 2개만 돌아옴 + "응답이 들쭉날쭉" → 같은 주소를 쓰는 장비가 둘. IP 충돌.

## 원격 접속(ssh)이 안 될 때
- ssh 도 네트워크를 타. 상대에게 주소가 없거나, DNS 장부의 주소가 틀렸거나, 길이 막혀 있으면 접속이 안 돼.
- `Could not resolve hostname` → 그 이름이 DNS 장부에 없어. 숫자 주소로 접속해 볼 수 있어.
- `Connection timed out` → 네트워크로는 닿지 않아. 그럴 땐 서버실의 그 서버 랙 앞(E)에 직접 가서 콘솔로 열면 돼. 네트워크가 망가졌을 때 쓰는 "직접 가서 키보드 꽂기"야.

## 장애 유형별 점검 순서
### A. 주소가 없음 (DHCP)
1. 서버에서 `ip addr` → inet 이 "(주소 없음)"이면 아직 주소를 못 받은 것.
2. `dhcp status` → OFF 이면 안내데스크가 문을 안 연 상태. 나눠준 주소 목록도 여기서 보여.
3. 안내데스크를 열면 DHCP 모드인 장비들이 몇 초 안에 주소를 받아.

### B. 이름을 못 찾음 (DNS)
증상 예: "web 서버가 db를 못 찾는대요! db가 누구야?"
1. 이름으로 ping 해보고, 숫자 IP로도 ping 해봐. 결과를 비교해.
   - 이름은 실패(Unknown host)인데 숫자는 성공 → 길은 멀쩡, 전화번호부가 문제.
2. 숫자 IP는 어디서 알아? `dhcp status` 의 나눠준 주소 목록, 또는 그 서버에서 `ip addr`.
3. `dns list` 로 장부를 열어서 그 이름이 적혀 있는지 확인. 없으면 등록해야 해.
4. 주소를 짐작해서 적으면 안 돼. 다른 장비의 주소를 적으면 "db"가 엉뚱한 장비로 가고 경보도 안 풀려. 대시보드에 "엉뚱한 장비가 응답함"이 뜨면 장부의 주소가 틀린 거야. (`dns add` 결과의 "참고" 줄도 그 주소를 지금 누가 쓰는지 알려줘)

### C. 응답이 들쭉날쭉 (IP 충돌)
증상 예: "DB 연결이 됐다 안 됐다 해요… 페이지가 반쯤 깨져요."
1. ping 을 여러 번 → 일부만 돌아오면 같은 주소를 쓰는 장비가 둘일 수 있어.
2. 서버마다 접속해서 `ip addr` 로 주소와 mode 를 비교해. `dhcp status` 목록에서 빠진 서버도 단서야.
   - 네트워크로 접속이 안 되는 서버가 있으면 그것도 단서야. 그 서버는 랙 앞에서 콘솔로 열어.
   - 정상: 모든 장비가 서로 다른 주소. (라우터·관리 PC는 원래 static)
   - 비정상: 두 장비가 같은 inet, 그중 하나는 mode static(손으로 박은 주소).
3. 손으로 박은 쪽을 안내데스크(DHCP)에서 자동으로 받게 바꾸는 게 근본 해결.
   - 급한 불은 겹친 장비 전원을 내려서 끌 수도 있어 (꺼진 장비는 대답을 못 하니까). 하지만 다시 켜면 또 충돌하니까 켜기 전에 주소부터 고쳐.
   - DB 쪽 주소를 옮기는 건 해결이 아니야. 그러면 "db" 이름이 겹친 장비로 가버려.
   - 다른 서버(예: web)의 주소로 옮겨도 충돌이 자리만 바뀌어. 대시보드에 "외부(학생) → web 응답이 들쭉날쭉"이 뜨고 경보도 안 풀려.

### D. 밖에서만 접속 불가 (게이트웨이)
증상 예: "학생들이 집에서 접속이 안 된대요. 관리 PC에서는 web 이 잘 보여요."
1. 건물 안(관리 PC → web)은 되고 밖(인터넷 → web)만 안 됨 → 안과 밖을 잇는 문을 의심.
2. 그 서버에 접속해서 `ip addr` → gateway 값을 봐.
3. 실제 라우터 주소(설계 보드 또는 라우터 콘솔의 `ip addr`)와 같은지 비교. 다르면 문 위치를 잘못 아는 것.
4. 고치는 방향은 서버 쪽 gateway 를 라우터의 진짜 주소로 맞추기 (DHCP로 다시 받아도 맞춰져). 라우터 주소를 바꾸는 건 안 돼.
- 라우터 콘솔에서 바깥(google.com)으로 ping 이 되면 라우터·인터넷 쪽은 멀쩡하다는 뜻이야.

## 힌트 줄 때 참고
- 정확한 IP 값이나 완성된 명령(인자 포함)은 말하지 마. "어디서 확인할 수 있는지"를 알려줘.
- 항상 "이름 vs 숫자", "안 vs 밖", "한 번 vs 여러 번"처럼 비교 실험을 권하면 좋아.
